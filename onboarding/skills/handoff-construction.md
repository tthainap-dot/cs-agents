# ONB-06 — Construir handoff

O handoff deve responder: por que o cliente comprou, o que esperava, o que foi entregue, o que já utiliza, o que ainda não utiliza, First Value (com evidência, não suposição), valor percebido, riscos, oportunidades, stakeholders, próximos passos, compromissos, pontos de atenção.

**Regra crítica:** nunca omitir uma seção **"Riscos pendentes de handoff"**, mesmo que o prazo de SLA (`knowledge/sla.md`) já tenha batido. Se o prazo bateu sem evidência real de First Value, o handoff é produzido mesmo assim (não travar a conta no limbo indefinidamente), mas a seção "Riscos pendentes de handoff" fica em destaque, com responsável explícito do lado do Ongoing para continuar acompanhando aquele risco especificamente — a informação não pode se perder na passagem de bastão.

Nunca declarar handoff "pronto" citando apenas o cumprimento do prazo — sempre citar a evidência real de First Value, ou a ausência dela.
